# CR-0002：S16 加入後端（py）測試套件

狀態：approved
核准者／時間：bonki

## 動機

S16-04 要求重生超出剩餘預算時再次確認。確認後要能真的重生，後端必須：(1) 提供每鏡重生所需點數（`ShotOut.regen_cost`），(2) 讓 regenerate 端點接受使用者同意的新成本上限並記錄核准。這些是 S16 規格 R-007 的後端補強。

`.tdd/progress.json` 中 S16 的測試套件只有 `web`、`e2e`，閘門不會執行標記為 S16 的 pytest，R-007 的後端程式碼會在沒有驗證的情況下通過閘門（與 CR-0001 相同的情況）。

## 影響範圍

| 項目 | 內容 |
|---|---|
| 需求／驗收條件 | S16 R-007、AC-007 |
| 場景 | 無變更（S16-04 使用新欄位） |
| API／資料 | `GET /videos/{id}` 每鏡加 `regen_cost`；regenerate 接受可選 `{cost_cap}`（只增不減） |
| 測試 | S16 的套件由 `["web", "e2e"]` 改為 `["py", "web", "e2e"]`；新增 `backend/tests/unit/test_regen_api.py`（`pytestmark = pytest.mark.S16`） |
| 成本 | 無 |

## 替代方案

- R-007 移到 S18（py 步驟）：S16 完成時「超出預算確認後重生」連接真實後端仍無法運作。
- 超出預算時直接禁止重生：與架構書 §6.4「否則暫停並詢問」不一致。

## 遷移或回滾方式

只修改 `.tdd/progress.json` 中 S16 的 `suites` 欄位。回滾時改回 `["web", "e2e"]` 並移除 `test_regen_api.py`。

## 要修改的檔案

- `.tdd/progress.json`：S16 的 `"suites": ["web", "e2e"]` → `["py", "web", "e2e"]`

由使用者核准後在終端機執行：`python3 scripts/tdd.py unlock CR-0002 .tdd/progress.json --minutes 10`，Claude Code 修改後再由使用者執行 `python3 scripts/tdd.py lock`。
