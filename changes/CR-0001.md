# CR-0001：S15 加入後端（py）測試套件

狀態：approved
核准者／時間：bonki

## 動機

S15 前端的角色擺放需要在實景照上顯示並拖曳角色去背圖，但現有 `GET /projects/{id}`（S08）只回傳物件儲存 key、沒有可載入的網址，回應也沒有型別（OpenAPI 產生的前端型別為任意物件）。S15 規格 R-007 因此要補強這個端點：改為具型別的 `ProjectOut`，並附上實景照與去背圖的預簽名網址。

`.tdd/progress.json` 中 S15 的測試套件只有 `web`、`e2e`。閘門只會為列有 `py` 的步驟執行 pytest，所以標記為 S15 的後端測試**不會被執行**，R-007 的後端程式碼會在沒有驗證的情況下通過閘門。

## 影響範圍

| 項目 | 內容 |
|---|---|
| 需求／驗收條件 | S15 R-007、AC-007 |
| 場景 | 無變更（S15-04 會使用新欄位） |
| API／資料 | `GET /projects/{id}` 回應加上 `character.cutout_url`、`scene_photos[].url`（只增不減） |
| 測試 | S15 的套件由 `["web", "e2e"]` 改為 `["py", "web", "e2e"]`；新增 `backend/tests/unit/test_project_api.py`（`pytestmark = pytest.mark.S15`） |
| 成本 | 無 |

## 替代方案

- 把 R-007 移到 S17（種子資料，py 步驟）：S15 期間前端只能以 mock 契約與暫時手寫型別開發，違反「API 型別由 OpenAPI 產生、不要手寫」。
- 把後端測試標記為 S08：會讓已完成步驟的證據混入新需求，不採用。

## 遷移或回滾方式

只修改 `.tdd/progress.json` 中 S15 的 `suites` 欄位。回滾時改回 `["web", "e2e"]` 並移除 `test_project_api.py`。

## 要修改的檔案

- `.tdd/progress.json`：S15 的 `"suites": ["web", "e2e"]` → `["py", "web", "e2e"]`

由使用者核准後執行：`python3 scripts/tdd.py unlock CR-0001 .tdd/progress.json --minutes 10`，修改後 `python3 scripts/tdd.py lock`。
